# v0.32.0 — Choice labels became real inline content

**Status:** shipped to `scriare/` on the user's machine. 94 tests green.
(v0.33.0, the toolbar rework, shipped on top of it — see the end.)

## What changed and why

A Choice Block used to be an atom node (`atom: true`) holding an `options`
array in a node attribute, each option's label a plain string. That made the
label invisible to the editor: marks apply to ProseMirror **text nodes**, and
there was no text node, so the toolbar could never style a choice no matter
how the UI was arranged. This was the blocking prerequisite for per-choice
visual styling (approach C, below).

New shape:

```
choiceBlock  content: "choiceOption+"   attrs: { blockId }
  choiceOption  content: "inline*"      attrs: { optionId, targetSceneId,
                                                 actions, conditions,
                                                 whenUnmet, style }
```

- `style` defaults to `null`, not `{}`, so "inherit the project default" is
  distinguishable from "explicitly the default" — the Inspector needs that to
  offer a reset.
- Structured lists (`actions`, `conditions`, `style`) serialise as JSON data
  attributes, because Play Mode renders through `generateHTML` and anything
  not serialised there is lost on the way.

## Traps found the hard way

- **`$pos.index()`, never `child === node`.** ProseMirror hands a NodeView a
  node equal to but not identical with the document's, so scanning the parent
  for an identical child matches nothing and every option renders as "1.".
- **Zero-length text nodes are rejected.** An empty label is `content: []`,
  not `[{type:"text",text:""}]`.
- **The ✕ on an option calls `removeChoiceOption`, not `deleteNode`.**
  `choiceOption+` forbids an empty block, so deleting the last option on its
  own leaves an invalid document; the helper takes the block with it.
- **Specs must build documents through `buildChoiceBlockNode`.** Three older
  specs seeded the legacy shape by hand and would have gone on reporting
  green while testing a document the app can no longer read.

## Migration

`migrateLegacyChoiceBlocks` (called from `normalizeProject`) handles two
generations — pre-v0.7.0 flat attrs, and pre-v0.32.0 `options` arrays — and
is a no-op on current content. It runs on **every** load, so idempotence is
load-bearing and is tested.

## Tests

`tests/choice-schema.spec.mjs` — 14 cases. Negative-controlled: migration
copying only the label, reorder dropping unmentioned options, last-option
removal leaving an empty block, and the runtime falling back to plain text
all fail the relevant case.

# v0.33.0 — The toolbar learns the app's icon language

**Status:** shipped. 101 tests green.

Chosen from an interactive mockup of three directions (A: letters set
properly · B: one icon language · C: grouped in tracks). The user picked
**B with C's colour swatches borrowed**.

- `components/common/Icon.tsx` gained 19 icons on the existing 16-unit grid
  at 1.3 stroke: heading1/2, bulletList, orderedList, quote, rule, the four
  alignments, fontFamily, fontSize, textColor, highlight, colorReset,
  clearFormat, branch, plus, properties.
- `components/editor/EditorToolbar.tsx` rewritten. Same controls, same
  order, same positions — only the drawing changed. B/I/U stay as
  letterform specimens (bold B, italic I, underlined U). Colour controls
  are a letter over a bar filled with the colour in effect; the two
  anonymous ✕ buttons became `colorReset` controls beside what they reset.
  The root carries `role="toolbar"`, which is also the tests' selector.
- **Contextual group**: `ChoiceContextGroup` renders when the selection's
  ancestors include a `choiceBlock`, and is **appended after** the insert
  button — never inserted mid-bar, or every control after it would shift
  under the writer's cursor. It holds "add another choice" and "choice
  properties" (which points the Inspector at that block rather than
  duplicating its controls).

### Icon lessons (all found by screenshotting the real app, not by reading)

- An outlined quotation curl at 16px collapses into the digits "66" — the
  quote marks had to be **filled**, not stroked.
- Stroked bullet dots read as smudges; fill them.
- An eraser glyph for "clear formatting" reads as an unidentifiable blob;
  the `Tx` convention is legible at this size.
- Arrowheads on the branch icon turn it into a squiggle at 15px; ending the
  prongs in filled dots reads cleanly.

`tests/toolbar.spec.mjs` — 7 cases on the two things that aren't taste: the
group **appends** (the label list before it is an exact prefix of the list
after), and **every control carries a label** (with icons there is no letter
left to read). Both negative-controlled.
